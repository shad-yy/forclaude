## Persona 1: Senior Front-End Developer

### 🔴 FE-1: `ignoreBuildErrors` and `ignoreDuringBuilds` both enabled
- **File**: `next.config.mjs` lines 7–11
- **Finding**: `eslint.ignoreDuringBuilds: true` and `typescript.ignoreBuildErrors: true` are both set, meaning TypeScript errors and ESLint violations ship to production silently.
- **Impact**: Broken components, runtime crashes, and type mismatches reach users without any CI gate.

### 🔴 FE-2: No `next/dynamic` usage — heavy dependencies loaded synchronously
- **Finding**: A codebase search reveals ZERO usage of `import dynamic from 'next/dynamic'`. Heavy libraries — `framer-motion` (~45 KB gzipped), `recharts` (~80 KB gzipped), `embla-carousel` — are all bundled synchronously into the initial JavaScript payload.
- **Impact**: Significantly increases First Load JS, harming INP and LCP scores.

### 🔴 FE-3: Raw `<img>` tags bypassing Next.js Image optimization
- **Finding**: Despite an excellent `<OptimizedImage>` wrapper existing at `components/ui/optimized-image.tsx`, many pages still use raw `<img>` tags (e.g., `app/match/[id]/page.tsx`, `components/homepage/match-card.tsx`, `app/watch/[slug]/page.tsx`).
- **Impact**: Bypasses WebP/AVIF conversion, responsive sizing, and lazy loading — directly hurting LCP and CLS.

### 🟡 FE-4: Missing Framer Motion hydration guards on some components
- **Finding**: Key components like `HeroSection` and `LiveStats` correctly use the `mounted` state guard, but other animated components (e.g., `ServicePillars`) do NOT use this guard.
- **Impact**: Potential hydration crashes in production (Bug 4 in Trouble Registry).

### 🟡 FE-5: Extensive `as any` usage throughout codebase
- **Finding**: 36+ instances of `as any` across the codebase. Major offenders:
  - `app/actions/subscribe.ts` (3 instances for globalThis rate limiting)
  - `app/api/auth/admin/route.ts` (5 instances for globalThis + JWT payload)
  - `lib/analytics.ts` (4 instances for window.gtag)
  - `components/analytics/WebVitals.tsx` (2 instances)
  - `components/consent/CookieBanner.tsx` (4 instances)
- **Impact**: Violates the project's own "No `any` type" rule. Type safety is undermined.

### 🟢 FE-6: CSS and Tailwind configuration is strong
- `globals.css` uses Tailwind `@layer` directives effectively, defines comprehensive sport-specific themes, and includes accessibility media queries for `prefers-reduced-motion` and `prefers-contrast`.

### 🟢 FE-7: Font loading is correct
- `next/font/google` with `Inter`, `display: "swap"`, and `preload: true` — no CLS from font loading.

### 🟢 FE-8: Error boundaries and loading states are well-implemented
- Global `error.tsx` and `not-found.tsx` exist with user-friendly UIs. `loading.tsx` with animated spinner exists. `Suspense` boundaries wrap many routes.

### 🟢 FE-9: Accessibility is strong
- Skip-to-content link in `layout.tsx`. Semantic HTML (`<header>`, `<nav>`, `<main>`, `<footer>`). ARIA attributes across interactive components. Focus ring styles in globals.css.

## Persona 4: Google Search Quality Rater

### 🔴 SEO-1: Canonical URL points ALL pages to homepage
- **File**: `app/layout.tsx` line 60
- **Code**: `alternates: { canonical: ENV.BASE_URL }`
- **Finding**: This is set in the ROOT LAYOUT, meaning EVERY page tells Google its canonical URL is `https://smartlivetv.co.uk`. Google sees all pages as duplicates of the homepage.
- **Impact**: **Catastrophic for SEO.** Google will refuse to index most pages. This single issue could be responsible for the site's position 36 average and 67 clicks over 3 months.

### 🔴 SEO-2: SportsEvent schema includes misleading Offer
- **File**: `lib/schema.ts` lines 56–63
- **Finding**: Every SportsEvent schema automatically includes an `Offer` with `price: "12.00"` pointing to `/pricing`. Google's guidelines require Offer schema to match exactly what is sold. The page sells a subscription, not a ticket to the event.
- **Impact**: Could trigger a structured data manual penalty or rich result demotion.

### 🟡 SEO-3: Organization schema uses wrong fallback URL
- **File**: `lib/schema.ts` line 88
- **Code**: `const baseUrl = process.env.NEXT_PUBLIC_APP_URL || "https://smart-live-tv.vercel.app"`
- **Finding**: The fallback URL is the old Vercel deployment URL, not the production domain.

### 🟡 SEO-4: Sitemap missing dynamic routes
- **File**: `app/sitemap.ts`
- **Finding**: The sitemap manually lists static routes but does NOT generate entries for `/match/[id]`, `/teams/[id]`, `/leagues` sub-pages, or `/ufc/events/[id]`.
- **Impact**: Dynamic content pages are invisible to search engines.

### 💡 SEO-5: No BreadcrumbList schema on most pages
- **Finding**: BreadcrumbList is only implemented on a few pages. Should be site-wide.

### 💡 SEO-6: No SpeakableSpecification schema for AEO
- **Finding**: No `SpeakableSpecification` schema for voice search and AI assistant readiness.
